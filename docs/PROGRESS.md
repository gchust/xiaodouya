# 功能进展

每个功能一行。**这里写的必须是已经发生的事实**：没跑过就写未验证，不写“应该没问题”。

## 怎么更新

- 开始做：把状态改成“开发中”，在“负责”里写分支名。别的 Agent 看到就不要重复做同一项。
- 做完或改了行为：在同一个 PR 里更新这一行，写明验证依据。
- 改动破坏了已验证的功能：把对应的验证退回 ⬜，放行改回“否”。
- 新功能：追加新行，用新编号。编号不复用，不改旧行的编号，这样并行开发时冲突最少。
- 只改自己负责的行，不顺手重排表格。

## 图例

**状态：** 未开始 / 开发中 / 待验证（代码已写，验证没做完）/ 完成

**验证：** ✅ 通过（写明依据）｜ ❌ 失败 ｜ ⬜ 未验证 ｜ — 不适用

- **单元：** 单元或集成测试。`shared`、`mobile`、`server` 指对应的测试包。
- **E2E：** Maestro 流程在 CI 通过，数字是流程编号。
- **真机：** 在真实手机上验证过。

**放行：** 可以给家人用。条件是这一行要求的验证全部 ✅。标着“需真机”的功能，没有真机验证就不能放行。
