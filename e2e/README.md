## 模拟器断开时整组重跑一次

CI 的模拟器偶尔会和 adb 断开几秒（见 `docs/PITFALLS.md` 的“CI”和“测试方法”）。流程不是幂等的，断在中间再跑同一条会被留下的数据干扰，所以 `e2e.sh` 遇到断开时**整组从头重跑一次**：重装 App、新的 `RUN_ID` 和账号，`verify-uploads.mjs` 只查新账号。

- 只有 Maestro 日志里这条流程的**第一个错误**是 `device offline`、`device '…' not found` 或 `DeviceServerDiedException` 才算断开，判断在 `scripts/e2e-env-failure.mjs`（有单元测试）。断言失败、找不到元素、App 崩溃都不重跑；断言失败之后才断开的，也算断言失败。
- 每组最多重跑一次，重跑时又断开就是失败。
- 重跑一定看得见：日志里有 `↻`，Actions 里有 warning，“CI 结果”的摘要列出每组重跑了几次、adb 实际断开了几次。第一次的调试输出在 `.artifacts/maestro-env-rerun-<分组>`。
- 现场记录：`.artifacts/adb-track.log`（adb 的每次状态变化）、`e2e-monitor.log`（每 20 秒的负载、CPU、内存、模拟器进程）、`adb-server.log`（CI 上收集）、`e2e-env-reruns.log`（每次重跑一行）。

本地 `pnpm e2e` 串行跑多组时，重跑会把整个 `.artifacts/maestro` 挪走，前面几组的截图也在挪走的目录里。

## 分组

CI 开四台模拟器，每台跑一组，各有自己的 Postgres、S3、服务端和账号，互不影响。**分组写在 [`groups.json`](groups.json)，是 CI 跑哪些流程的唯一依据。**

| 分组 | 内容 | 前置 |
| ---- | ---- | ---- |
| `family` | 回忆上传和查看、证件、搜索、头像、出生档案、小金库、退出再登录、只看的家人、一起记录的家人 | 注册，记一剂卡介苗 |
| `vaccine` | 身高体重、疫苗本、改疫苗日期、补记睡眠和身高体重、回忆的封面（放这组因为它最短）、换地区、主题配色、系统大字体、应用内更新和自动下载新版本、反馈问题 | 注册 |
| `daily` | 建档（流程 01）、连点只记一条、日常记录、喂奶和营养、离线、分享一天和时间线、分享设置、小工具链接和“桌面小工具”页、换语言 | 无，流程 01 自己注册 |
| `files` | 批量上传、上传控制、家人协作、存储设置、改回忆和证件、分享回忆、育儿资料和收藏、删除账号 | 注册 |

**加流程时要做：** 放进 `e2e/flows`，在 `groups.json` 里加进一个分组（挑最短的、前置满足的）。依赖别的流程就写进 `requires`，`a|b` 表示有其中一个就行。`pnpm check` 里的 `node scripts/e2e-groups.mjs check` 会检查：

- 每条流程必须且只能属于一个分组，没分配就失败。
- `requires` 的前置在同一组且排在前面。
- 组内按文件名排序（串行时验证过的就是这个顺序，“要在谁之前”都靠它）。
- `endOfGroup` 的流程后面不能接别的流程：20、21 跑完不是管理员，22 跑完停在登录页。
- `uploadChecks` 引用的流程都还在。

**前置**放在 `e2e/setup`，不算流程，也不做断言：`onboard` 注册建档（流程 01 用 `runFlow` 复用它，断言留在流程 01），`record-bcg` 记一剂卡介苗（`family` 组的流程 19 要看到已接种）。

**`verify-uploads.mjs` 按组查：** 每组都核对这组所有对象的状态、大小和内容。“有回忆原图”“有分片上传的大文件”“有证件 PDF”“有证件照的缩略图，600×400 的样例缩到长边 256”“头像旋转裁剪过”“反馈的照片重新编码过、没有 EXIF，公开链接跳到它”只在跑了对应流程的组里查（见 `uploadChecks`），加起来一条不少。反馈那条还要连 `e2e.sh` 起的服务端（`E2E_API_URL`，默认 8787）和假 GitHub（`E2E_FAKE_GITHUB_URL`，默认 8790）。预览和缩略图不能带 EXIF、证件缩略图长边不超过 256 这两条每组都查这组有的对象；“有预览”“带 GPS 的样例原图和它的预览、缩略图”只在跑了流程 03a 的组里查。

CI 和本地的服务端都用 `apps/server/.env.example`，里面开着自定义存储，所以管理员在流程 07 看到的是 S3 表单。用量页（线上托管模式时所有人看到的页面）由流程 21 用一起记录的家人覆盖。“托管模式下管理员看到用量页”这一条要换服务端配置，E2E 没有覆盖，只有单元测试。

CI 的 E2E 环境没有配置邮件，所以邮箱验证、找回密码没有 Maestro 流程，由服务端集成测试覆盖。

反馈（流程 24）连 `e2e.sh` 启动的假 GitHub（`apps/server/test/fake-github.ts`，端口 8790），绝不连真实的 GitHub。服务端的 `FEEDBACK_*` 由 `e2e.sh` 在启动时传进去，不写进 `.env.example`；8787 上已经有别的服务端在跑时，`e2e.sh` 直接用它，那个服务端没有这几项的话流程 24 会失败。“这台服务器暂不支持”要换服务端配置，由服务端测试和手动走查覆盖。

收到的反馈（流程 25）的维护者邮箱 `feedback-maintainer@example.test` 由 `e2e.sh` 写进服务端的 `FEEDBACK_VIEWER_EMAILS`：服务端启动时还没有 `RUN_ID`，只能用固定的邮箱。`e2e/helpers/feedback-maintainer.js` 先删掉上一次留下的同名账号（本地开发库跨次保留），再注册、加入这次的家庭，并在接口上核对管理员是 403、列表里没有提交者的邮箱。手动在别的端口跑时传 `--env BASE=http://localhost:<端口>`。名单外和没配置时的 403、过期附件、限流由服务端测试覆盖。

## 用什么是真的，什么是模拟的

| 环节                           | 情况                                                     |
| ------------------------------ | -------------------------------------------------------- |
| 服务端、数据库、同步           | 真实                                                     |
| 预签名直传、S3 协议            | 真实（SeaweedFS，S3 兼容）                               |
| 上传后的校验                   | `verify-uploads.mjs` 直接查库并从 S3 读回对象，预览和缩略图不能带 EXIF |
| 第二位家人、只看回忆的家人     | 脚本走真实接口                                           |
| 系统相册和相机                 | E2E 构建用内置样例代替，系统界面随版本变化，自动化不稳定 |
| 保存到系统相册                 | 真实，`e2e.sh` 收尾时查系统媒体库                        |
| 系统文件夹选择器               | E2E 构建换成 App 内的固定目录，之后的复制和重名处理是真的 |
| 分片上传、取消                 | 真实（流程 03a、03b 的样例里有一张超过阈值的图）。断点续传要断网或杀 App，靠单元测试和手动验证 |
| Cloudflare R2、AWS S3 本身     | 没有测，需要真实账号                                     |
| 后台上传、推送到达、厂商杀后台 | 模拟器测不了，发版前要在真机上验证                       |
